# UbiBot Open 系统部署、烧录与联调指南

本文档面向想要把 `ubibot-open-server`、`ubibot-open-ws1b`、`ubibot-serial-sync` 三个仓库串起来、
从零跑通一条"设备联网 → 上报数据 → 后台可见"完整链路的使用者。设备↔服务端的协议细节见
[硬件通信协议](../protocol/UbiBot开放平台硬件通信协议.md)，本文档只讲怎么把每个组件跑起来、以及
怎么把它们接到一起。

> 仓库名称说明：以下命令里的仓库名以本组织（`ubibot-open`）当前实际 GitHub 地址为准
> （核心平台历史上叫 `ubibot-platform-open`，固件叫 `ubibot-ws1b`）；如果你这边已经把它们改名成
> `ubibot-open-server` / `ubibot-open-ws1b`，直接用新仓库地址 clone 即可，不影响后续步骤。

## 0. 系统组成一览

```
┌─────────────────┐   BLE配网(协议§1，暂未实现)   ┌──────────────┐
│  手机/PC App     │ ─────────────────────────▶  │  ubibot-open- │
└─────────────────┘                              │  ws1b 固件设备 │
                                                  └──────┬───────┘
                                                         │ HTTP (协议§2~§8)
                                                         │ POST /api/v1/auth/time
                                                         │ POST /api/v1/data/report
                                                         ▼
┌────────────────────┐   串口(USB)   ┌──────────────────────────────┐
│ ubibot-serial-sync  │◀────────────▶│      ubibot-open-server        │
│ 桌面串口调试工具      │  查看日志/调试  │ Go 后端 + 内嵌 React 管理后台     │
└────────────────────┘               │ 单一可执行文件，SQLite 存储       │
                                      └──────────────────────────────┘
                                              ▲
                                              │ 浏览器 http://<host>:8080
                                              │
                                      ┌───────┴───────┐
                                      │   管理员浏览器   │
                                      └───────────────┘
```

三个组件各自独立部署，之间只通过网络（设备→后端的 HTTP）和物理连线（PC→设备的 USB 串口）耦合，
没有共享代码或共享配置文件。

## 1. 环境准备

| 组件 | 用途 | 需要的环境 |
|---|---|---|
| `ubibot-open-server` | 设备接入后端 + 管理后台，编译为单一可执行文件 | Go 1.23+、Node.js/npm（构建管理后台前端时需要） |
| `ubibot-open-ws1b` | WS1B 设备参考固件（目标芯片 ESP32-C5） | ESP-IDF v6.0.2 |
| `ubibot-serial-sync` | 桌面端串口调试工具 | 直接下载官方预编译包即可，**无需自行构建**；要从源码构建见该仓库的 `BUILD.md`（Qt 6 / CMake / C++17） |

## 2. 部署并启动后端服务（ubibot-open-server）

### 2.1 获取源码

```bash
git clone https://github.com/ubibot-open/ubibot-platform-open.git ubibot-open-server
cd ubibot-open-server
```

### 2.2 一键构建

```bash
./build.sh        # Linux / macOS
# .\build.ps1      # Windows
```

构建脚本做两件事：编译 `admin/` 下的 React 管理后台，产物内嵌进
`server/internal/webui/dist`；再编译 Go 后端，产出仓库根目录下的单一可执行文件
`ubibot-server`（`CGO_ENABLED=0`，纯 Go 实现的 SQLite 驱动，静态二进制，不需要额外安装
运行时或数据库服务）。

### 2.3 启动

```bash
./ubibot-server
```

默认监听 `:8080`，数据库文件默认写在 `./data/ubibot.db`（首次启动自动创建目录和库文件）。
可用环境变量覆盖：

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `UBIBOT_LISTEN_ADDR` | `:8080` | 监听地址 |
| `UBIBOT_DB_PATH` | `./data/ubibot.db` | SQLite 数据库文件路径 |
| `UBIBOT_ADMIN_PASSWORD` | （不设置则随机生成） | 仅在库内一个管理员账号都没有时（即首次启动）生效，用户名固定为 `admin` |

首次启动、且没有预先设置 `UBIBOT_ADMIN_PASSWORD` 时，日志会打印类似下面这行：

```
no admin account found — created "admin" with a generated password: 3f9a1b2c4d5e6f
```

**这行密码只打印这一次**，请立刻记录；也可以提前设置好
`UBIBOT_ADMIN_PASSWORD=<自定义密码>` 环境变量后再第一次启动，跳过随机密码。

首次启动还会自动创建一个演示设备（`pid=ubibot_open_dev_v1`，`sn=sn_ws1_20001_1`），
可以在管理后台设备列表里先看到它，用来确认后台本身工作正常，不必等真实硬件联网。

### 2.4 登录管理后台

浏览器打开 `http://localhost:8080`（API 和管理后台由同一个进程、同一个端口提供），用上一步
的 `admin` 账号密码登录。

## 3. 烧录 WS1B 参考固件（ubibot-open-ws1b）

### 3.1 获取源码，安装 ESP-IDF

```bash
git clone https://github.com/ubibot-open/ubibot-ws1b.git ubibot-open-ws1b
cd ubibot-open-ws1b
```

需要 **ESP-IDF v6.0.2**（目标芯片 **ESP32-C5**），按 Espressif 官方文档安装好后，每次开新的
终端会话都要先激活环境（`. ./export.sh` 或 Windows 下的 `export.ps1` / ESP-IDF 自带的
"Command Prompt"/"PowerShell"快捷方式），确保 `idf.py` 命令可用。

### 3.2 配置设备参数

```bash
idf.py set-target esp32c5   # 首次构建需要；已经生成过 build/ 目录可跳过
idf.py menuconfig
```

进入 `UbiBot WS1B Configuration` 菜单，按需修改：

| 子菜单 | 配置项 | 默认值 | 说明 |
|---|---|---|---|
| WiFi Configuration | WiFi SSID | `TEST24` | 设备联网用的 WiFi 名称 |
| | WiFi Password | 空 | 留空表示连接开放（无密码）网络 |
| | WiFi country code | `01` | 两字母国家码（如 `CN`/`US`），或 `01` 表示世界通用安全默认值 |
| Server Configuration | Data server host | `192.168.2.71` | 第 2 步部署的后端所在 IP/域名 |
| | Data server port | `8080` | 需与后端 `UBIBOT_LISTEN_ADDR` 对应的端口一致 |
| Device Identity | Device product ID | `ubibot-ws1b` | 同一型号设备可以共用 |
| | Device serial number | `RV41554WS1B` | **每台实体设备必须改成唯一值**，量产批次不要共用同一个 SN |

配置保存在本地的 `sdkconfig` 文件（已加入 `.gitignore`，不会被提交），默认值定义在
`main/Kconfig.projbuild`。

> **和协议文档的差异说明**：本参考固件的联网参数是**编译期写死进 `sdkconfig`**的，不是
> [硬件通信协议](../protocol/UbiBot开放平台硬件通信协议.md) §1 描述的"蓝牙配网"——每次要改
> WiFi 或服务器地址，都需要重新 `idf.py menuconfig` 并重新烧录一次，不能在设备运行时通过 App
> 现场配置。蓝牙配网是协议层面规定的能力，尚未在这版参考固件里实现。

### 3.3 编译并烧录

```bash
idf.py build
idf.py -p <串口号> flash monitor
```

`<串口号>` 例如 Windows 下的 `COM5`、Linux 下的 `/dev/ttyUSB0`、macOS 下的
`/dev/cu.usbserial-xxxx`。`flash` 烧录完会自动进入 `monitor` 串口日志模式，可以直接看到设备
启动、连接 WiFi、上报数据的完整过程；按 `Ctrl+]` 退出 monitor。

## 4. 用串口调试工具查看/调试设备（ubibot-serial-sync）

用途：查看设备串口日志、手动收发数据，不依赖 ESP-IDF 环境（尤其适合设备已经量产烧录、
不方便在目标机器上装 ESP-IDF 的场景），跨平台图形界面比 `idf.py monitor` 更好用。

### 4.1 获取

优先直接下载预编译包，不需要安装 Qt 或任何构建工具：

| 平台 | 下载 |
|---|---|
| Windows | [UbiBotSerialAssistant-windows-x64.zip](https://github.com/ubibot-open/ubibot-serial-sync/releases/latest/download/UbiBotSerialAssistant-windows-x64.zip) |
| macOS | [UbiBotSerialAssistant-macos.dmg](https://github.com/ubibot-open/ubibot-serial-sync/releases/latest/download/UbiBotSerialAssistant-macos.dmg) |
| Linux | [UbiBotSerialAssistant-linux-x86_64.AppImage](https://github.com/ubibot-open/ubibot-serial-sync/releases/latest/download/UbiBotSerialAssistant-linux-x86_64.AppImage)（`chmod +x` 后直接运行） |

首次运行会被系统当成"未知发布者"拦一下（Windows SmartScreen / macOS Gatekeeper），和其他未
签名的开源软件一样，点击继续运行（或 macOS 上右键→打开）即可，这是正常现象。

### 4.2 连接设备

1. 打开软件，在"串口连接"面板选择设备对应的串口号，波特率与固件 UART 日志输出的波特率一致
   （ESP-IDF 默认 115200）。
2. 点击打开端口，右侧数据监控面板会实时显示彩色区分的 TX/RX/SYS/ERR 日志，效果和
   `idf.py monitor` 类似，但不需要装 ESP-IDF。
3. 需要主动发送内容时，用手动发送框（支持 ASCII/HEX），或在"设备指令库"面板里按型号选择
   预置命令模板。

> 目前设备指令库里还没有收录 WS1B 的预置命令集（这个库是纯 JSON 配置驱动的，新增型号只需
> 加一份 JSON、无需改代码），暂时用手动发送框即可满足调试需求。

## 5. 端到端验证：设备联网并上报数据

按顺序确认下面几个现象，哪一步不对照对应小节排查：

1. **设备侧**：`idf.py monitor`（或 serial-sync 的日志面板）里能看到设备打印类似
   "WiFi connected"、拿到 IP 地址的日志。
   → 看不到：检查第 3.2 步的 WiFi SSID/密码/country code 是否配对，或路由器/AP 是否可达。
2. **网络与协议**：日志里出现对 `POST /api/v1/data/report` 的调用，响应是 `{"c":0,...}`。
   → 一直拿不到响应或超时：确认第 2 步后端进程已启动、`Data server host/port` 填的是后端实际
   监听的地址和端口，以及运行后端的主机防火墙是否放行了该端口。
3. **后台可见**：回到管理后台（`http://<后端地址>:8080`）的设备列表，能看到刚才配置的 SN 自动
   出现——协议规定设备首次成功上报即自动建档，不需要在后台预先创建。设备最新一条数据可以在
   "数据仓库"页看到。

三步都通过，说明"设备联网 → 上报数据 → 后台可见"这条主链路已经跑通。

## 6. 不依赖真实硬件的联调方式（可选）

`ubibot-open-server` 仓库自带一个纯 C 编写的设备仿真程序（`simulation/` 目录），实现了和真实
固件完全一致的协议行为，适合在没有硬件在手、或者只想快速验证后端/管理后台改动时使用：

```bash
cd ubibot-open-server/simulation
cmake -S . -B build
cmake --build build
./build/ub_device_sim --host 127.0.0.1 --port 8080
```

默认参数对应后端首次启动自带的演示设备（`sn_ws1_20001_1`）；也可以用 `--pid`/`--sn` 指定别的
设备身份——协议不需要预先注册设备，服务端收到首次上报会自动建档。`--tick-ms` 可调整主循环
心跳间隔（默认 1000ms），`Ctrl+C` 结束仿真进程。

## 7. 常见问题

| 现象 | 对应错误码 | 原因与处理 |
|---|---|---|
| 上报被拒绝，`c=1002` | 时间戳超出 ±5 分钟窗口 | 设备本地时钟漂了；确认设备在收到该错误后有主动调用 `POST /api/v1/auth/time` 校准 |
| 上报被拒绝，`c=1003` | 请求体格式错误 | 检查固件端 JSON 序列化逻辑是否符合协议 §5 |
| 上报被拒绝，`c=1103` | 设备已被后台禁用 | 去管理后台设备详情页把状态改回启用 |
| 上报被拒绝，`c=1900` | 触发限流 | 上报过于频繁；等下一个周期重试，或检查设备是否在异常重发 |
| 设备日志一直连不上后端 | 无响应/超时 | 确认 `Data server host/port` 填对、后端进程在运行、主机防火墙放行了 `UBIBOT_LISTEN_ADDR` 对应端口，且设备和后端在同一网络可达 |
| 忘记管理后台密码 | — | 停止 `ubibot-server` 进程，用 `sqlite3` 打开数据库执行 `DELETE FROM admin_users;` 清空管理员表，再启动服务——会按 §2.3 的逻辑重新走一遍"首次启动"流程，生成新的 `admin` 账号（不影响设备数据） |
