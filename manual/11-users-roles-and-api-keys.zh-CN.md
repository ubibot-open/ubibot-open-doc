# 用户、角色与 API 密钥

*[English](11-users-roles-and-api-keys.md)*

**系统**下有三个相关的页面：谁能登录（**管理员**）、他们能做什么（**角色**），以及控制台之外
谁能读取数据（**API 密钥**）。

## 角色

进入**系统 → 角色**，点击**新建角色**。一个角色包括：

- **名称** —— 显示用的标签。
- **代码** —— 一个简短的标识符（比如 `operator`）。**创建后不可修改**——填错了只能删掉重建，
  不能改代码本身。
- **权限** —— 一组勾选框，对应平台的四个权限码：`device:read`、`device:write`、
  `alert:manage`、`system:manage`。只授予这个角色真正需要的权限——这几个权限之间没有隐含的
  "有读就有写"或者任何层级关系。

**截图占位符：** `11-users-roles-and-api-keys-01.png` —— 新建角色的表单，能看到权限勾选框。

> **注意：** 平台第一次运行时会预置一个内置的超级管理员角色（见[第 2 章](02-deploy-server.zh-CN.md)），
> 不管它存储的权限是什么，永远能通过所有权限检查——这是一个固定的安全阀,防止你自己建的角色配错了
> 权限,把所有管理员一次性锁在外面。

## 管理员账号

进入**系统 → 管理员**，点击**新建管理员**。设置**用户名**、**密码**，分配一个**角色**。编辑一个
已有的管理员，可以单独重新分配角色和/或重置密码（密码字段留空就保持不变），两者互不影响。

**截图占位符：** `11-users-roles-and-api-keys-02.png` —— 管理员列表，编辑表单打开的状态。

不能删除你当前登录用的这个账号——那样会把你自己登出，而且没有明显的办法能再登进去，除非有另一个
管理员出面处理。

## 开放 API 密钥

进入**系统 → API 密钥**，点击**新建密钥**——唯一需要填的字段是**名称**，方便你以后记住这是干
什么用的。提交之后，明文密钥会**只显示这一次**，放在一个可复制的文本框里：

**截图占位符：** `11-users-roles-and-api-keys-03.png` —— 一次性显示的密钥，能看到复制按钮。

现在就把它复制下来——服务器只会存它的哈希值，关掉这个对话框之后就再也没有办法把它取回来了。如果
丢了，去列表里撤销这个密钥，再新建一个。密钥本身没有角色或权限范围的概念——它只有"有效"或"已撤销"
两种状态，能访问的就是《[开放 API 参考](../api/open-api.zh-CN.md)》里列出的那些只读接口。
