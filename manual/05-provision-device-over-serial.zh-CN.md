# 通过串口配置设备

*[English](05-provision-device-over-serial.md)*

你在[第 4 章](04-flash-firmware.zh-CN.md)里用 `menuconfig` 设置的值只是出厂默认值。这一章会
通过同一个串口，在运行时把它们覆盖掉，不需要重新构建或烧录——WiFi 网络、服务器地址，以及（如果
你是用一份构建烧录了整批设备）这台设备自己的序列号。

## 1. 打开 ubibot-serial-sync 并连接

启动 [ubibot-serial-sync](https://github.com/ubibot-open/ubibot-serial-sync/releases/latest)。
在串口连接面板里，选中设备所在的端口，波特率设为 **115200**（跟固件的日志/控制台 UART 一致）——
端口选择器会把可能是设备的端口（CH340/CP210x 这类 USB 转串口芯片）标为推荐。打开端口。

**截图占位符：** `05-provision-device-over-serial-01.png` —— 串口连接面板，选中并连接了正确的
端口，数据监控面板里已经在滚动开机日志。

## 2. 重新打开配网窗口

设备只在**刚上电之后**的一小段时间内监听配网指令——串口静默 5 秒后会自动关闭，或者总时长满
60 秒后关闭，哪个先到就按哪个算，而且普通的定时唤醒不会重新打开这个窗口。如果你已经错过了这个
窗口（比如刚才在看这一章而不是在敲命令），只需要给设备重新上电——拔插一下 USB 数据线，或者按一下
复位按钮——就能重新打开一个新的窗口。

## 3. 设置 WiFi 网络

在手动发送框里（右侧数据监控面板，不管当前显示哪个面板都一直可见）输入：

```json
{"command":"SetupWifi","ssid":"YourNetworkName","password":"YourPassword","type":"WPA2"}
```

然后发送。如果是开放网络（没有密码），把 `password` 省略或留空即可。

> **注意：** 协议要求必须带上 `type` 这个字段，但目前的固件只是把它存起来——还没有真正用它来
> 决定连接时用哪种认证方式（底层的 WiFi 驱动会自己协商）。为了以后的兼容性，还是照常发一个值过去
> （有密码的网络用 `WPA2`，没密码的用 `OPEN`）。

留意日志里返回的应答：

```json
{"c":0,"msg":"wifi saved"}
```

**截图占位符：** `05-provision-device-over-serial-02.png` —— 手动发送框里输入了 `SetupWifi`
指令，上方日志里能看到 `{"c":0,...}` 的应答。

`c: 0` 表示成功。`c: 1` 表示缺了什么字段或者格式不对（改好重发即可——窗口时间还没到，因为每收到
一个字节都会重置那个 5 秒静默倒计时）。`c: 2` 表示格式校验通过了，但实际保存失败——比较少见，
重试一下就行。

## 4. 设置服务器地址

```json
{"command":"SetupServer","host":"192.168.1.100","port":8080}
```

要用运行 `ubibot-server` 那台机器（见[第 2 章](02-deploy-server.zh-CN.md)）在局域网里的 IP
地址——不要用 `127.0.0.1`/`localhost`，那样会让设备指向自己。`port` 要跟 `UBIBOT_LISTEN_ADDR`
设置的端口一致（默认是 `8080`）。

## 5. （仅批量烧录的设备需要）设置这台设备的序列号

如果你烧录的这台设备在 `menuconfig` 里已经写好了自己独一无二的序列号，这一步可以跳过。如果你是
用同一份构建（相同的 `pid`，相同的默认 `sn`）烧录了整批设备，现在给这台物理设备一个属于它自己的
序列号：

```json
{"command":"SetupDevice","sn":"a-unique-value-for-this-unit"}
```

`pid` 没有对应的指令可以改——同一份固件构建出来的每一台设备，本来就应该共用同一个 `pid`。

## 6. 确认生效了

这三项设置都会**立刻**生效，就在设备当前这次运行期间——不需要重启。串口日志应该很快就能看到设备
连上新的 WiFi 网络，并向新的服务器地址成功上报。它们也会保存到非易失存储里，所以即使断电或者进入
深度睡眠再唤醒，这些设置都还在，直到你再次给设备配网为止。

**截图占位符：** `05-provision-device-over-serial-03.png` —— 配网之后，串口日志显示设备连上
WiFi 并成功发出一次上报。
